# 售后答案格式

当前 Agent 内部使用 Pydantic `SupportAnswer` 结构化输出，并由 runtime 渲染成以下中文客服参考格式。SDK output guardrail 会在渲染前检查结构化输出；runtime 还会对最终中文文本做本地 contract 校验。

每次终端回答必须遵守以下结构和字段顺序：

```text
AI 客服参考

问题类型：
product_usage / troubleshooting / quality_issue / ticket_followup / unknown

运行模式：
Agent SDK

置信度：
高 / 中 / 低，并说明原因。

用户问题摘要：
...

SKU 命中：
- 如果命中：SKU / SPU / 品名 / 产品负责人 / 命中置信度
- 如果未命中：未在 SKU 目录中命中；需要补充订单 SKU、包装 SKU、产品铭牌或图片。

建议回复（供客服参考，可复制调整）：
...

建议排查步骤：
1. ...
2. ...
3. ...

需要追问：
- ...

正式依据：
- 文档名称 / 章节 / 链接
- 如果未查询到：未查询到可信正式依据，不可编造。

历史参考：
- 相似案例摘要 / 日期 / 链接
- 如果未查询到：未查询到可信历史参考，不可编造。

工单草稿：
- 如果需要：标题 / 问题描述 / 缺失信息 / 建议负责人 / 优先级 / 下一步
- 如果不需要：不建议生成工单，并说明原因。
```

## 依据规则

- SKU 字段只能来自 `search_sku_catalog` 或用户消息本身。
- 正式依据只能来自已接入的正式知识库/RAG 结果。
- 历史参考只能来自已接入且已审核的案例卡片结果。
- 如果检索工具说明未接入或没有命中，答案必须说明没有找到可信依据。
- 不得编造文档名、章节、链接、历史案例、批次结论、负责人、政策或技术结论。

## 置信度规则

- 高：已接入的正式依据直接匹配产品和问题，或回答仅限于直接 SKU/产品识别。
- 中：SKU/产品身份清楚，但排查建议仍需要确认，或上下文仍有缺失。
- 低：没有正式依据、没有已审核历史案例、SKU 不明确，或用户消息过短。

SKU 命中置信度和整体答案置信度是两件事。精准 SKU 命中可以让 `SKU 命中` 高置信，但如果正式知识库和已审核历史检索都没有命中，整体答案置信度必须为低。

低置信度时，答案必须提醒客服在回复客户前人工确认。
