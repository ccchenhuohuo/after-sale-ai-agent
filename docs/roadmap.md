# MVP 路线图

## 阶段 0：准备

交付物：

- LLM API key 已写入 `.env`。
- 20-50 篇核心正式文档。
- 50 个已标注售后问题。

当前状态：

- Agents SDK 终端运行时已可通过 `VIJIMcopilot` 启动。
- 合并后的 SKU 支持目录已生成在 `data/sku_catalog/processed/<date>/`。
- Web Demo、HTTP API、webhook 运行时和本地确定性分析器已从当前测试阶段移除。
- 阶段 0 剩余阻塞项是：经过审核的正式知识库、经过审核的历史案例卡片、已标注评测问题，以及生产级源数据导出。

## 阶段 1：终端 Agent 循环

目标：

```text
启动终端 -> 输入客服问题 -> VIJIM-after-sale-copilot 返回结构化参考答案。
```

交付物：

- 简单终端对话。
- `/status`、`/help`、`/bye` 等命令。
- Agents SDK tracing。
- 严格答案格式。
- 不再使用本地规则生成售后建议。

## 阶段 2：Agent 循环

交付物：

- `VIJIM-after-sale-copilot` Agent。
- Prompt 和输出格式。
- 基础日志。

## 阶段 3：正式知识库

目标：

```text
Agent 可以基于正式产品文档回答问题。
```

交付物：

- 人工导出流程。
- Markdown 清洗。
- 元数据标注。
- 分块。
- Embedding。
- 正式知识库检索工具。

## 阶段 4：历史案例

目标：

```text
Agent 可以引用相似的已解决案例。
```

交付物：

- 历史问答清洗。
- 案例卡片。
- Embedding 聚类。
- 去重。
- 已验证、已解决标签。
- 历史案例检索工具。

## 阶段 5：工单草稿

目标：

```text
复杂问题可以生成需要人工确认的工单草稿。
```

交付物：

- 工单草稿工具。
- 严重程度规则。
- 缺失信息检测。
- 建议负责人字段。

## 阶段 5.5：已审核品质跟进写入

目标：

```text
经过人工审核的售后事件可以整理为品质跟进 Base 记录。
```

交付物：

- 售后事件字段到 `客户反馈表` 的映射。
- 默认值：`数量 = 1`，`是否个案 = 是`。
- CQE、责任部门、异常分类、状态、问题来源、处理方案的受控词表。
- 写入前必须人工确认。
- 内部处理方案和客户承诺保持清晰分离。

## 阶段 6：评估

目标：

```text
衡量 AI 是否提升售后支持效率和答案质量。
```

交付物：

- 检索命中率评估。
- 答案质量评审。
- 客服采纳率。
- 坏案例分析。
- Prompt、分块和元数据优化。
